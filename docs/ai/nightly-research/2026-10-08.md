## Security Risks

### P0 — Next.js `16.2.6` is behind several security releases
Sources: [Next.js security release roundup (lilting.ch)](https://lilting.ch/en/articles/nextjs-security-release-16-2-6-15-5-18), [August 2026 release writeup (aicybr)](https://aicybr.com/blog/nextjs-august-2026-security-release-rce-remediation), [July 2026 release (DEV)](https://dev.to/mr_manushukla/nextjs-july-2026-security-release-9-cves-patched-in-16211-and-15521-3o9b), [Next.js GitHub releases](https://github.com/vercel/next.js/releases).
- Reported: July (`16.2.11`, 9 CVEs: 4 high, 5 medium); August (`16.3.3`: AVIF image-optimization RCE, CVSS 9.5 reported, and CVE-2026-75604 on Windows filesystems, CVSS 9.0 reported); the 10-06 report lists further fixes in `16.3.8`. The `16.4.0` release page showed no security-labelled entries.
- Applicability: this project deploys Linux containers, so the Windows-only issue likely does not apply. The AVIF issue applies only if image optimization is used. Whether `frontend/next.config.*` configures `images` has not been confirmed in a full read, from either the 10-04 or 10-06 cycles.
- Per `AGENTS.md`, a dependency bump needs a stated justification and human approval. Run `npm test && npm run lint && npm run build` after.

### P0 — Starlette floor (*carried*)
`backend/requirements.txt` has `starlette>=0.49.1`. The installed version is unverified. A higher floor, plus `pip show starlette` in the running container, is recommended.

### P1 — PostgreSQL image currency
Sources: [Releasebot / AhnLab summaries of the May 2026 release](https://asec.ahnlab.com/en/93764/).
- The May 2026 release fixed 11 CVEs, including CVE-2026-6476 (SQL injection in `pg_createsubscriber`), CVE-2026-6477 (libpq large-object stack overflow), CVE-2026-6478 (MD5-auth timing side channel) and CVE-2026-6472 (`CREATE TYPE` authorization). A rating of CVSS 8.8 for CVE-2026-6637 comes from a single aggregator and is *unverified*.
- Action: pull and recreate `postgres:16-alpine`, then confirm with `SELECT version();` (expect 16.14 or later). Compose files in both dev and prod use the floating tag, which also means the running version depends on when the image was last pulled.

### P1 — Redis image (*carried*)
`redis:7.4.9-alpine` is pinned in both compose files. The 10-06 report cites 2026 Redis CVEs (use-after-free CVE-2026-23479, `RESTORE` CVE-2026-25243). This cycle did not re-check which 7.4.x tag fixes them. Exposure depends on Redis being reachable only on the internal Docker network.
