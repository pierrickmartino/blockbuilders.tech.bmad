## Executive Summary

**A new, critical, unauthenticated Next.js RCE landed as an out-of-band release on 2026-09-22 (CVE-2026-94545 / GHSA-vcvr-r3jv-pc5j), and — unlike the framework-level advisories tracked in prior cycles — this repo has a concretely exploitable-shaped surface for it.** `next/og`'s `ImageResponse` (Node.js runtime) has an SVG-escaping RCE inherited from an upstream Satori bug; fixed in Next.js `16.3.6`. This repo imports `next/og` in `frontend/src/app/share/backtests/[token]/opengraph-image.tsx` — a **public, unauthenticated route** (shared backtest results). The interpolated fields there are constrained (asset from an allow-listed enum, timeframe enum, numeric return/drawdown/sparkline coordinates — the component's own comment states "strictly result-only, no strategy graph or idea/name"), which narrows the practical exploitability versus the advisory's free-text `<title>` example, but does not eliminate it, and the fix is a version bump with no code changes required. This is now the **third** unpatched critical/high Next.js RCE stacked on the repo's `16.2.6` pin (alongside the AVIF RCE and Windows path-traversal RCE flagged for 9 consecutive cycles), and Next.js has now announced a **fourth** release, `16.3.7`/`15.5.27`, scheduled for 2026-09-30, fixing nine more vulnerabilities (1 critical, 2 high, 5 medium, 1 low) under its new monthly security-release program (first announced July 2026). The `next` bump recommendation, flagged for 9+ cycles, should be treated as materially more urgent than before.

**Starlette's BadHost CVE-2026-48710 is now confirmed independently as actively exploited in the wild, with a public PoC/scanner tool on GitHub** (`Bhanunamikaze/BadHost-CVE-2026-48710-Exploit`) — new information this cycle, not previously surfaced. Given active exploitation, this evidence gap matters more today than it did five days ago.

Live Docker Hub tag inspection confirms `7.4.10-alpine` and `7.4.11-alpine` both exist and are pullable now. The standing recommendation (bump to `7.4.11-alpine`) is unchanged in *direction* but its priority should move up given the newly-detailed RCE-via-RDB-load fix bundled in.

## Security Risks

### P0, NEW this cycle — Next.js `next/og` ImageResponse RCE (CVE-2026-94545 / GHSA-vcvr-r3jv-pc5j), fixed in 16.3.6, and this repo has a live usage site
Out-of-band advisory published 2026-09-22: improper SVG escaping in the upstream Satori dependency, reachable through Next.js's Node.js-runtime `ImageResponse` implementation (`next/og`), can lead to remote code execution when untrusted content reaches SVG output (advisory's own example: a `searchParams` value wired into an SVG `<title>`). Affects Next.js `>=16.2.0 <16.3.6`; the Edge `ImageResponse` implementation is **not** affected; Next.js `15.x` gets a hardening-only release (`15.5.26`), not the RCE fix (not applicable — RCE doesn't affect 15.x).
- **This repo uses `next/og`:** `frontend/src/app/share/backtests/[token]/opengraph-image.tsx`, a public unauthenticated route rendering shared backtest cards. Confirmed by reading the file — interpolated values are `asset` (allow-listed enum per `product.md` §3.4), `timeframe` (enum), and numeric return/drawdown/sparkline-path values; no free-text strategy name or idea reaches the SVG (the component's own comment states this explicitly). This narrows exploitability relative to the advisory's free-text example but does not eliminate it, since the underlying Satori escaping bug is independent of what specific content triggers it.
**Action:** bump `next` `16.2.6` → at least `16.3.6` (patches this + the two RCEs already flagged for 9 cycles). A fourth release, `16.3.7`/`15.5.27`, is scheduled for 2026-09-30 fixing 9 more vulnerabilities (1 critical, 2 high, 5 medium, 1 low) — worth bumping straight to whichever is current once that lands rather than stopping at `16.3.6`.

### P1, more severe than previously characterized — Redis: `7.4.9-alpine` gap now spans 5 bundled security fixes across two releases, including an RDB-triggered RCE
Docker Hub confirms `7.4.9-alpine` itself is untouched (`last_updated: 2026-05-09`), but live tag inspection this cycle confirms both `7.4.10-alpine` (2026-07-26) and `7.4.11-alpine` (2026-09-21) exist and are pullable. Between them they fix:

**Action (unchanged direction, higher priority):** bump `redis:7.4.9-alpine` → `redis:7.4.11-alpine` in both compose files.
