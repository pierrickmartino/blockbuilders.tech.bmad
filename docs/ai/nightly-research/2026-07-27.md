## Security Risks

### P1, CONFIRMED (re-verified independently today) — Next.js: 9 CVEs (4 HIGH, 5 MODERATE), fixed in 16.2.11; repo still on vulnerable 16.2.6
Re-confirmed directly against `nextjs.org/blog/july-2026-security-release` and current `npm view next version` (latest: 16.2.12, unchanged since 07-25):

| Severity | CVE | Summary |
|---|---|---|
| HIGH | CVE-2026-64641 | DoS in App Router using Server Actions |
| HIGH | CVE-2026-64642 | Middleware/Proxy bypass in App Router + Turbopack + single locale |
| HIGH | CVE-2026-64645 | SSRF in rewrites via attacker-controlled destination hostname |
| HIGH | CVE-2026-64649 | SSRF in Server Actions on custom servers |
| MODERATE | CVE-2026-64643 | Unauthenticated disclosure of internal Server Function endpoints |
| MODERATE | CVE-2026-64644 | DoS in Image Optimization API using SVGs |
| MODERATE | CVE-2026-64646 | Unbounded Server Action payload in Edge runtime |
| MODERATE | CVE-2026-64647 | Cache confusion via invalid UTF-8 byte sequences |
| MODERATE | CVE-2026-64648 | Cache confusion of response bodies for requests with bodies |

All ranges `>=16.0.0, <16.2.11`; repo's pinned `16.2.6` is inside every one. No revisions or additions to this list found today. Repo-exposure narrowing from prior cycles stands: no `middleware.ts`, no `rewrites()`/custom `images` config, no custom server file, no WebSocket usage, no `"use server"` anywhere in `frontend/src` — narrows exposure for most advisories, but the two App-Router-internal ones (Server Actions DoS; internal Server Function endpoint disclosure) live in Next.js's own request-handling path regardless of app code.
**Action:** bump `"next": "16.2.6"` → at least `16.2.11`, or straight to `16.2.12` (current latest) in `frontend/package.json`. Patch-level bump; `npm install && npm run build && npm run lint` should suffice.
