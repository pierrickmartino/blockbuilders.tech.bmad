### OPEN, refined this cycle — Starlette version floor below CVE-2026-48710 ("BadHost") fix, but likely not live-exploitable in fresh builds
See the Executive Summary nuance above: `starlette>=0.49.1` (unbounded, no lockfile) will resolve to the latest available Starlette (currently 1.3.1, patched) on any fresh `pip install`, since nothing in the dependency graph — including `fastapi==0.136.1`'s own `starlette>=0.46.0` floor — caps it lower. ### #510 — Pydantic → Zod codegen seam
**One new adjacent reference surfaced.** `zod-from-json-schema` (npm) is actively maintained as of June 2026, but it takes a different approach than the previously-noted `json-schema-to-zod`/`@dmitryrechkin/json-schema-to-zod`: it builds Zod types from a JSON Schema **at runtime**, rather than generating source code at build time. That runtime-vs-codegen distinction matters for this repo's use case (Strategy validator shared seam) — a codegen approach keeps the generated Zod schema inspectable and lintable in the frontend repo, while a runtime approach adds a dependency and indirection at request time for no clear benefit here. Standing recommendation unchanged: prefer the codegen path (`@dmitryrechkin/json-schema-to-zod` fork) if this direction is chosen. No tool anywhere auto-generates the cross-field validator this issue actually needs (take-profit ladder ascending-order + ≤100%-total check) — still requires hand-written `.refine()`/`@field_validator` pairs on each side. `pydantic2zod` (argyle-engineering) remains the closest Python-side option, model-shape only.

### #511 — Atomic `submit()` / commit-then-enqueue seam
**Nothing new this cycle.** Standing recommendation unchanged: a transactional-outbox table (write the job row in the same DB transaction, a separate step/worker relays it to Redis) remains the right-sized fix; `django-rq`'s `COMMIT_MODE='on_db_commit'` remains the closest packaged reference for the "commit-then-enqueue" semantic, with no raw-RQ + SQLModel equivalent existing as a library.

### #334 — PostgreSQL 18 evaluation
PostgreSQL 19 Beta 2 (2026-07-16) is new context: the next major is now actively progressing toward release while this repo hasn't started evaluating 18. Nothing else new beyond the version/CVE state already covered above.
