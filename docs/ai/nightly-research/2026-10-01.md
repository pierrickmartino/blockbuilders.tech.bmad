## Executive Summary

1. **The Next.js September security release shipped on 2026-09-30 as `16.3.8` / `15.5.27`.** The pre-announcement was revised twice:
   - It first said nine fixes, including one critical and two high.
   - It now says seven fixes: one high, five medium, one low.
   - The critical and one high issue are deferred pending upstream coordination, so **another Next.js release should be expected**.
   - `16.3.7` (2026-09-29) is a bug-fix release only and does not contain the security fixes. The 2026-09-26 report expected the fixes in `16.3.7`; that was wrong. The target is `16.3.8`.
2. **The repo is still on `16.2.6`.** It is exposed to every unpatched Next.js advisory flagged in earlier cycles, plus the new set:
   - the `next/og` ImageResponse RCE (GHSA-vcvr-r3jv-pc5j);
   - the AVIF and Windows path-traversal RCEs;
   - the new high-severity image-optimization SSRF;
   - several cache-poisoning and cache-leak issues.
   
   The repo uses `next/og` on the public route `frontend/src/app/share/backtests/[token]/opengraph-image.tsx`. **Bumping `next` to `16.3.8` is the single highest-value action.**
3. **Starlette BadHost (CVE-2026-48710) is still unaddressed in the repo.** `backend/requirements.txt` has only `starlette>=0.49.1`. A fresh install resolves to `1.7.0`, which is safe. The deployed container has not been verified. Two further Starlette CVEs surfaced in this cycle's search (CVE-2026-48818, fixed in 1.1.0; CVE-2026-54283, fixed in 1.3.1), so a floor of `>=1.3.1` covers all three.
4. **Redis `7.4.9-alpine` is still pinned** in the prod compose file. The 2026-09-26 report gives the detail of the fixes in `7.4.10`/`7.4.11`. Bump to `7.4.11-alpine`.
5. **Supply-chain check: the Keyv/"Shai-Hulud" npm compromise does not affect this repo's lockfile** (details under Security Risks).
6. **No issue-state change.** All ten tracked issues are unchanged. The three `ready-for-agent` PRDs (#618, #570, #555) are still blocked on human PostHog configuration.

## Security Risks

### P0 — Next.js `16.2.6` is behind a stack of fixed vulnerabilities
- **Fixed in `16.3.8` (2026-09-30), per the release notes:**
  - High: SSRF in Image Optimization.
  - Medium: information disclosure in App Router metadata image routes via a `dynamicParams` bypass.
  - Medium: cache poisoning of SSG/ISR pages in self-hosted deployments (two entries).
  - Medium: `use cache` fill leaking Draft Mode content.
  - Medium: cache leak across root param values in nested `use cache`.
  - Low: information disclosure on the dev server's MCP endpoint.
  
  I fetched the release notes but did not read the full advisories, so CVE and GHSA ids and exact affected ranges for these are not captured here.
- **Fixed earlier, still open at `16.2.6`:**
  - `next/og` ImageResponse RCE (GHSA-vcvr-r3jv-pc5j / CVE-2026-94545), fixed in `16.3.6`.
  - AVIF Image Optimization RCE and Windows path-traversal RCE, both fixed in `16.3.3`.
- **Repo relevance:**
  - `next/og` is imported in `opengraph-image.tsx` on the public share route. Per the previous report, the interpolated values are enum or numeric, which narrows but does not remove the exposure.
  - The repo is self-hosted via Docker Compose, which is the condition named for the cache-poisoning advisories.
- **Pending:** one critical and one high vulnerability are deferred to a later release. Watch the Next.js security blog.
- **Action:** bump `next` and `eslint-config-next` together to `16.3.8` (patch-level within 16.x, so it should be low-risk). This needs a human-approved PR, and the `AGENTS.md` rules require an explanation for any dependency change.

### P0 — Starlette (FastAPI core)
- BadHost, CVE-2026-48710 / GHSA-86qp-5c8j-p5mr: fixed in `1.0.1`. Reported as exploited in the wild, with a public PoC; CISA KEV deadline was 2026-09-16.
- Other Starlette CVEs in a search result: CVE-2026-48818 (fixed in `1.1.0`) and CVE-2026-54283 (fixed in `1.3.1`). I did not open these advisories.
- This repo: `starlette>=0.49.1` allows vulnerable versions. A fresh resolve gives `1.7.0`. The deployed image's version is unknown.
- **Action:** raise the floor to at least `starlette>=1.3.1` in `backend/requirements.txt`, then check with `pip show starlette` in the running backend container. FastAPI `0.136.1` may constrain the Starlette range, so test the resolve before committing. One search result recommends moving FastAPI to `^0.141.0` and relocking.
- **Why a human gate:** this touches the auth-adjacent request path, so `AGENTS.md` requires approval.

### P1 — Redis `7.4.9-alpine`
- CVE-2026-81934 (TLS pending-data use-after-free, CVSS 7.5) is fixed in `7.4.11`. This repo uses plain `redis://`, so that specific bug is not reachable here.
- The previous report records further fixes in `7.4.10` and `7.4.11` (stream `RESTORE` use-after-free, ACL bypass, RDB-load memory corruption). Those details are carried over from that report, not re-verified.
- **Action:** bump `redis:7.4.9-alpine` → `redis:7.4.11-alpine` in the compose files.

### P2 — npm supply-chain incident ("Shai-Hulud" / Keyv, advisory dated 2026-08-06)
- Compromised versions: `keyv@6.0.0`, `flat-cache@6.1.24`, `file-entry-cache@11.1.6`, `cacheable-request@13.0.20`, `cacheable@2.5.1`.
- `frontend/package-lock.json` has `keyv@4.5.4`, `flat-cache@4.0.1`, `file-entry-cache@8.0.0`, and no `cacheable` or `cacheable-request`. These are not the compromised versions. This is likely ESLint's dependency chain.
- **Residual risk:** a lockfile regeneration or a loose `npm install` could pull a compromised range. Use `npm ci` in CI and Docker. I did not audit CI configuration in this pass.
- A separate May 2026 compromise (TanStack and 160+ packages) was reported in search. The repo uses `@tanstack/react-query`. I did not check which TanStack packages and versions were affected. Verify against the vendor advisory.

### Informational
