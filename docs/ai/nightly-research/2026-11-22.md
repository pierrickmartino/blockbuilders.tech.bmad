## Executive Summary

1. **Open issues are unchanged from yesterday.** The three `ready-for-agent` issues (#618, #570, #555) are each blocked on a `ready-for-human` PostHog task (#620, #573, #561). There is no agent-actionable work.
2. **Still no issue tracks the Next/React bump.** `next` 16.2.6 and `react` 19.2.6 are both in vulnerable ranges. Target `next` ≥ 16.4.5 and `react`/`react-dom` ≥ 19.2.9 (or 19.3.1). This is a human decision per `AGENTS.md`.
3. **React RSC RCE (GHSA-xqc2-xf4c-x3h3, CVE-2026-126187, CVSS 9.5).** Search sources agree on the fixed versions: 19.0.9, 19.1.10, 19.2.9 and 19.3.1. The affected packages are `react-server-dom-webpack`, `-parcel` and `-turbopack`. Our `react` 19.2.6 sits in the affected range 19.2.0–19.2.8. One source says updating React alone does not fix Next.js. The fix for the Next-bundled copy comes with the Next upgrade (16.4.1 or later per that source). Fix date is Nov 10 in most sources. One Korean blog says Oct 14, so the date is unresolved.
4. **Next.js November release (2026-11-03).** It covers seven advisories, fixed in 16.4.5 and 15.5.29. Netlify rates them Medium. One third-party write-up says one High and six Medium, and its "2 RCEs" headline is unsupported by the other sources. Next 15 gets security releases until 2027-01-31 per one write-up. Details were not verified at the primary source.
5. **PostgreSQL 19 reached GA on 2026-11-19** (the postgresql.org news post, EDB and LinuxCompatible agree). This resolves yesterday's open question. The official 19.0 release-notes page still shows a placeholder date. Issue #334 is scoped to PG 18, and 19 is days old.
6. **PostgreSQL security batch (2026-11-12).** The batch fixes 52 CVEs in 18.7, 17.12, 16.16, 15.20 and 14.25. Headline CVE-2026-6460 is an authenticated type confusion bug that can lead to code execution. IDs vary across write-ups. PG 14 is now EOL. We use the floating `postgres:16-alpine` tag in both compose files, so prod gets the fix only after a pull and recreate.
7. **FastAPI version data conflicts.** Releasebot lists 0.162.x through 0.165.0 in November, including a drop of Python 3.10 support (0.163.0), AnyIO ≥ 4.1.0 (0.162.4) and configurable request body size limits (0.165.0). The official release-notes pages in the search results are stale (top entries from July to September). Treat the aggregator numbers as unverified. We pin 0.136.1.

- **FastAPI.** Read the English notes at fastapi.tiangolo.com/release-notes/ and the GitHub releases before any bump. Cross-check against the aggregator's claims. Test with the pinned SQLModel and Pydantic. If the 0.163.0 drop of Python 3.10 is real, it does not affect us (Python 3.12).
- **`@xyflow/react`.** 12.11.2 is the newest found. The 2026-07-06 entry is about performance. Our `^12.10.0` range already allows it. Run `npm view @xyflow/react version` to confirm nothing newer exists.
- **Tailwind / TypeScript.** Nothing found. Tailwind stays on v3. A v4 migration would be a separate scoped task.
- **Docs drift.** `AGENTS.md` says "Next.js 15" while `CLAUDE.md`, `product.md` and the pin say 16.x. A human should approve the fix.
- **Visual strategy builder UX** (blog and vendor sources, not formal research):
  - The recurring pattern is hybrid: generate a working draft, show it as a node graph, keep nodes single-purpose, and give fast backtest feedback. This matches our wizard (§4.4), canvas (§4), templates (§3.7) and the #618 NL-wedge idea.
  - Raven pulls options from a pasted market URL and offers a repeat node. Composer uses one block per operation. ChartEA Builder uses sentence-like condition popups, similar to our Explanation Generator (§4.8).
  - ClashX builds on xyflow, linking condition nodes to action nodes.
  - NinjaTrader opens generated code as an escape hatch. Our export (§3.5) covers JSON only.
  - Reviewers note that advanced features end up gated behind code and that some tools have a learning curve for non-traders.
  - Not researched: port typing, inline validation and backtest-feedback patterns in node editors.
