### P1, target updated (11th consecutive cycle tracking this component) — Redis: fix target moves from `7.4.10-alpine` to `7.4.11-alpine`
`redis:7.4.11-alpine` was pushed to Docker Hub **2026-08-20** (confirmed live via Docker Hub v2 API today), superseding `7.4.10-alpine` (2026-07-26, the previously-recommended target for CVE-2026-66373). Redis's own GitHub release notes for `7.4.11` list five fixes — TLS use-after-free on connection close race, an ACL key-permission bypass in `SORT`/`GEORADIUS`/`GEORADIUSBYMEMBER`/`XREAD`/`XREADGROUP` (validated keys can differ from accessed keys), an OOB `argv` read during ACL key extraction on wrong-arity `KEYNUM` keyspec commands (e.g. `EVAL`), an RDB `SLOT_INFO` out-of-range slot-id bug causing memory corruption "which may lead to Remote Code Execution," and a blocked-client-list use-after-free — **but the release notes do not assign CVE IDs to any of these**. **Caution:** a widely-circulated CVE ID, CVE-2026-62356, is sometimes associated with this release in secondary sources, but direct inspection shows it actually describes a **RedisBloom** (module) CMSketch RDB integer-overflow/heap-OOB-write bug, not the core-Redis `SLOT_INFO` issue — treat that CVE mapping as unconfirmed/likely-wrong until Redis publishes an official ID for the core fixes.
**Action (updated):** bump `redis:7.4.9-alpine` → **`redis:7.4.11-alpine`** (not 7.4.10) in `docker-compose.yml` + `docker-compose.prod.yml`. One-line, no-code-impact fix.
