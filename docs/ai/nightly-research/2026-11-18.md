## Executive Summary

1. **PostgreSQL released a large security batch on 2026-11-12 (confirmed on postgresql.org).** Fixed in 18.7, 17.12, 16.16, 15.20 and 14.25. The page lists 50+ CVEs, many CVSS 8.8 (arbitrary code execution as an authenticated user). We run `postgres:16-alpine`, a floating tag. A fresh `docker compose pull` should get 16.16, but the running prod container only updates when it is pulled and recreated. **Action: confirm the prod DB is on 16.16.** PG 14 is now EOL, which does not affect us.
2. **Possible new critical React Server Components RCE: unverified, and I could not confirm it.** Search results cite "CVE-2026-126187" (fixed in 19.2.9 / 19.3.1, published 2026-11-10) and a Canadian bulletin AV26-1152. But the react.dev blog index shows no security post after December 2025, and the CVE number format looks odd. Treat as a lead only. A human should check the GitHub advisory page and `npm view react versions` before acting. Our pin is `19.2.6`, below the claimed fix. Whether we are exposed is unknown. The earlier report noted no `use cache` or Edge usage, but RSC is on by default in the App Router.
3. **Next.js pin `16.2.6` is behind the 2026-11-03 patched line (`16.4.5`).** Same as last night. Exposure looks low but unproven. A bump should be planned alongside the React question above.
4. **FastAPI is 27 minors behind (`0.136.1` vs `0.163.2`).** The release notes flag a "Breaking Changes" section in **0.162.6** (2026-11-13). I could not read its contents. Read it before any bump.
5. **Open issues unchanged.** `ready-for-agent`: #618, #570, #555, each blocked on a `ready-for-human` PostHog task (#620, #573, #561). Nothing is actionable by an agent.
