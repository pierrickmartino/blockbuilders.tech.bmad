## Security Risks

### P0 — Next.js `16.2.6` behind the 2026-10-14 update
Sources: [Netlify changelog, Oct 14 2026](https://netlify.com/changelog/2026-10-14-nextjs-react-security-vulnerabilities), [Singapore CSA alert AL-2026-148](https://www.csa.gov.sg/alerts-and-advisories/alerts/al-2026-148/), [Canadian Cyber Centre AV26-851](https://cyber.gc.ca/en/alerts-advisories/nextjs-security-advisory-av26-851).
- Three issues: an SVG/Image Optimization RCE, a `use cache` RCE, and a Server Actions DoS. Fixed in `16.4.1` and `15.5.28`; 16.x before `16.4.1` is affected.
- Repo exposure (checked in the repo): no `"use server"`, no `"use cache"`, no `next/image`, no `sharp`, `node:20-alpine` base image. Likely not exploitable as described, but I did not verify against the primary advisories.
- Recommendation: propose a `risk-medium` task to bump to `next@16.4.1` or a newer 16.x patch. It crosses two minors (16.2 to 16.4), so run `cd frontend && npm test && npm run lint && npm run build` and read the 16.3 and 16.4 release notes first. Needs human approval.

### P1 — Starlette / FastAPI (carried)
- June 2026 Starlette CVEs from yesterday's report (Host header validation, path handling, urlencoded-body DoS) have unconfirmed affected ranges. `starlette>=0.49.1` is only a floor. Run `pip show starlette` in the backend image. Auth-adjacent, so pin changes need human approval.

### P1 — PostgreSQL and Redis
- PostgreSQL: [AhnLab ASEC advisory](https://asec.ahnlab.com/en/95023/) describes a fix line (14.24, 15.19, 16.15, 17.11, 18.5), including an arbitrary code execution flaw in logical decoding (CVE-2026-6471). The date was not shown. `postgres:16-alpine` floats, so a rebuilt image should pick up the fix; confirm the deployed image is on 16.15 or later. Logical decoding is likely unused here, which lowers exposure.
- Redis: [AV26-859](https://cyber.gc.ca/en/alerts-advisories/redis-security-advisory-av26-859) lists fixes for Redis 8.x only; the repo runs `7.4.9`. Whether 7.4.x is affected was not checked. Confirm Redis is not publicly exposed and requires auth.
- RQ: no advisories found, but the search returned nothing about RQ at all, so this is absence of coverage.

- **Visual strategy builder UX** (vendor pages, low rigor): [Backtrex](https://backtrex.com/en/docs/getting-started/introduction) structures the canvas as indicator, logic and action blocks, and applies anti-repainting safeguards (signals use confirmed bar data). [Vantixs](https://hunted.space/product/vantixs) pairs drag-and-drop nodes with backtest, walk-forward and Monte Carlo validation and surfaces risk and assumptions before deployment. A [DEV post](https://dev.to/siddharthaghosh/the-evolution-of-no-code-ux-what-makes-a-flow-builder-maintainable-21eh) argues flows should be reviewable by technical and non-technical people together. Product fit: the explanation generator (§4.8), inline validation (§4.9) and health bar (§4.17) already cover readability. The gaps are robustness checks beyond one backtest (the planned multi-period batch, §5.1, is closest) and an explicit statement that signals execute at the next candle open (§5.3 already specifies this; surfacing it in the UI is the idea).
