### RESOLVED-TO-CONTAINED — npm "ChainDrop" supply-chain worm: confirmed contained, repo unaffected throughout
Follow-up on the `keyv`/`cacheable`/`flat-cache`/`file-entry-cache` worm disclosed 2026-08-04: npm began pulling poisoned versions within ~2 hours of detection on the day it broke, and a clean `keyv@6.0.0` has been re-published via npm Trusted Publishers with SLSA provenance. Peak spread was reported as ~444 packages/2,212 versions within the first 4 hours, with later tallies around 868 packages/1,381 versions (sources vary; Microsoft Security Blog and StepSecurity both corroborate containment, not continued spread). No search results dated 2026-08-05 through 2026-08-07 show new packages added to the compromised list beyond the original 2026-08-04 blast radius, and no chalk/debug/ansi-styles-style follow-on campaign was found.
**Repo-specific status (unchanged from 2026-08-04, re-confirmed):** `frontend/package-lock.json` resolves only pre-existing safe major versions (`keyv@4.5.4`, `flat-cache@3.2.0`/`4.0.1`, `file-entry-cache@8.0.0`) via ESLint/Storybook dev tooling, not runtime code; none of `cacheable`, `cacheable-request`, `cache-manager`, `@cacheable/utils` appear in the lockfile at all. `npm ci` in CI installs exactly the lockfile's resolved versions.
**Action:** the standing caution ("don't run `npm update` or regenerate the lockfile for caching-adjacent packages") can reasonably be relaxed now that the campaign is confirmed contained and clean versions are re-published — but there's no urgency to do so either way since the repo was never exposed.
