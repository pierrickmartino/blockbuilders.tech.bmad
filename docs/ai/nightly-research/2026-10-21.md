## Security Risks

### P0 — Next.js `16.2.6` behind the 2026-10-14 update (*official*)
Source: [Next.js Security Update, Oct 14 2026](https://nextjs.org/blog/nextjs-security-update-october-14-2026). Fix: `npm install next@16.4.1`.
- **Critical, GHSA-673q-mjm6-r5xr:** unauthenticated RCE when an App Router app with Cache Components has a `use cache` function returning multiple typed arrays. No workaround. Upgrade even if no such function exists. Related React advisory: GHSA-xqc2-xf4c-x3h3.
- **Critical, CVE-2026-96889 / GHSA-2464-fhr4-w9xw:** RCE in the Image Optimization API with SVG on glibc Linux, via the `sharp` dependency. Workaround: `sharp` 0.35.5 or later. Alpine images use musl, so exposure may differ; verify the frontend image base before assuming safety.
- **High, GHSA-p3m5-59mp-jv5r:** CPU-exhaustion DoS in App Router apps with at least one Server Action. Related React advisory: GHSA-h3gv-c5rc-p453. Check whether the repo uses Server Actions.
- Earlier undeployed fixes still apply: the July `16.2.11` release (nine CVEs, including a middleware auth bypass) ([secondary](https://dev.to/mr_manushukla/nextjs-july-2026-security-release-9-cves-patched-in-16211-and-15521-3o9b)) and the 2026-09-22 update (fixed in 16.3.6) ([official preview](https://nextjs.org/blog/upcoming-nextjs-security-release-september-22-2026)). I did not read the September advisory text.
- Not checked: whether the repo uses `use cache` / Cache Components, `next/image` with SVG, or Server Actions. Do that before judging exploitability, but the upgrade is advised regardless.
- Needs human approval (`AGENTS.md`: dependency change, auth-adjacent). Verify with `cd frontend && npm test && npm run lint && npm run build`. The React pin may also need a bump to match the related React GHSAs.

### P0 — Starlette (actively exploited, *secondary*)
Sources: [SentinelOne CVE-2026-48817](https://www.sentinelone.com/vulnerability-database/cve-2026-48817/), [Anyscale bulletin](https://docs.anyscale.com/security/bulletins/260528-badhost.md), [Vulert CVE-2026-48817](https://vulert.com/vuln-db/starlette-is-a-lightweight-asgi-framework-toolkit-in-versions-1-0-1-and-below-when-dispatching-a-r-).
- CVE-2026-48710: Host-header handling bypasses path-based auth middleware. Fixed in 1.0.1; CISA KEV on 2026-09-02 per one source.
- CVE-2026-48817: non-standard HTTP verbs reach internal helper methods. Sources disagree on the fix (1.1.0 vs "1.0.1 and below affected"). Published 2026-06-17.
- Action: run `pip show starlette` in the backend image. Pin `starlette>=1.1.0` if FastAPI `0.136.1` allows it, or bump FastAPI. Compatibility with FastAPI 0.136.1 is **unverified**. Confirm against the upstream advisories first. Auth-adjacent, so human approval is required.

### P1 — PostgreSQL May 2026 release (*secondary*)
Sources: [AhnLab CVE-2026-6476](https://asec.ahnlab.com/en/93764/), [Vulert CVE-2026-6637](https://vulert.com/vuln-db/red-hat-security-advisory-postgresql-security-update--15).
- Fixes land in 18.4, 17.10 and the matching 16.x/15.x/14.x minors. CVE-2026-6476 is a SQL injection in `pg_createsubscriber`, which is unlikely to be used here. Vendor-package CVEs (RHEL) are not necessarily relevant to the Docker image.
- Action: `docker compose exec db postgres --version`. Consider a pinned minor tag instead of floating `16-alpine`.

### P2 — Redis server (*secondary, low confidence*)
- An aggregator lists CVE-2026-66373, CVE-2026-72568 and CVE-2026-81934 (CVSS 7.5, no detail) plus CVE-2026-23479 (ACL, fixed in May releases) ([Vulert](https://vulert.com/vuln-db/red-hat-security-advisory-redis-7-security-update--4)). The repo pins `redis:7.4.9-alpine`. Check redis.io advisories for a newer 7.4.x. Make sure Redis is not exposed outside the Compose network.
- No RQ vulnerability turned up. This is absence of evidence, not a clean bill.
