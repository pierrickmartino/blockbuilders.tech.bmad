## Implementation References

### #509 — Block Catalogue dispatch-table refactor
**Nothing new.** No packaged codemod exists for migrating `explanation.py`'s three ladders and `explanation-generator.ts`'s fifth fork onto the `block_type`-keyed catalogue pattern `interpreter.py` already uses. General AST-rewrite infrastructure (`ast-grep`, Codemod CLI) exists but has no prebuilt rule for this shape — still a manual refactor.

### #510 — Pydantic → Zod codegen seam
**One notable status change.** The base `json-schema-to-zod` package is now confirmed **unmaintained as of March 2026**, and its own docs explicitly state JSON Schema and Zod don't map 1:1 — cross-field refinements (this issue's actual need: take-profit ladder ascending-`profit_pct` + `close_pct` total ≤100%) are never generated and must be hand-added via `.refine()`. This doesn't change the standing recommendation (prefer the `@dmitryrechkin/json-schema-to-zod` fork for codegen over the runtime `zod-from-json-schema` approach) but is a reason to explicitly verify the fork's own maintenance status before committing to it in a spec. No tool anywhere (checked again this cycle) auto-generates cross-field validators from Pydantic `@model_validator`/`@field_validator` into Zod `.refine()` — still requires hand-written pairs on each side.

### #511 — Atomic `submit()` / commit-then-enqueue seam
**New concrete option surfaced.** [`outbox-streaming`](https://github.com/hyzyla/outbox-streaming) (Python) explicitly supports the **RQ + SQLAlchemy + Redis** combination this repo uses — a relay process reads an outbox table and enqueues to Redis, giving "commit-then-enqueue" semantics without hand-rolling the relay. This is a closer match to this repo's exact stack than the previously-noted `django-rq` `COMMIT_MODE='on_db_commit'` reference (Django-specific) and is worth evaluating directly in the eventual spec. Alternative surfaced for contrast: dropping Redis/RQ entirely in favor of Postgres `LISTEN/NOTIFY` + `SELECT...FOR UPDATE SKIP LOCKED` — benchmarked at ~52k jobs/hr vs. ~180k for Redis+BullMQ, with caveats (lost notifications on listener disconnect, `NOTIFY` takes a global commit lock, breaks under transaction-mode PgBouncer). Given this repo already runs Redis/RQ in production, `outbox-streaming` is the more right-sized fix; the Postgres-only path is noted for completeness, not recommended.

### #334 — PostgreSQL 18 evaluation
New performance data point (see Findings for Active Issues above): 20–30% OLTP short-query throughput gains reported for PG18, relevant to this repo's write-heavy ingest + read-heavy analytical backtest profile. PG19 still Beta 2, unchanged since 2026-07-16.
