Repo's current pins (`redis==7.1.1`, `rq==2.7.0`) are mutually compatible today and unaffected. Guardrail unchanged: **do not bump `redis` past 7.x without bumping `rq` to >=2.9.1 in the same change.**

### #510 — Pydantic → Zod codegen seam
**Nothing materially new.** Re-confirmed this cycle: `json-schema-to-zod` has been unmaintained since March 2026 (still functional, supports Zod v3/v4 output); `zod-to-json-schema` similarly unmaintained since November 2025 (superseded by Zod v4's native JSON Schema support). `@dmitryrechkin/json-schema-to-zod` remains the actively-maintained fork to prefer. `pydantic2zod` (argyle-engineering) is still the closest Python→Zod option but only handles model shape, not cross-field validators. No tool found anywhere auto-generates the cross-field validator this issue needs (take-profit ladder ascending-order + ≤100%-total check) from a single source of truth — still requires hand-written `.refine()`/`@field_validator` pairs on each side.

### #511 — Atomic `submit()` / commit-then-enqueue seam
**One adjacent reference surfaced, not a direct fit.** A Redis engineering writeup (["Building Reliable Agents with the Transactional Outbox Pattern and Redis Streams"](https://dev.to/redis/building-reliable-agents-with-the-transactional-outbox-pattern-and-redis-streams-45e6)) describes using Redis Streams itself as the durable outbox/commit-log, rather than a separate relational outbox table. This is architecturally interesting but not a drop-in fit here: it assumes Redis Streams as the primary queue, whereas this repo's task queue is RQ (list-based, not Streams-based) — adopting it would mean swapping queue technologies, well outside this issue's scope of "make the existing RQ enqueue atomic with the DB commit." The Python-specific `hyzyla/outbox-streaming` library checked this cycle is also not applicable — it targets Kafka. Standing recommendation unchanged: a transactional-outbox table (write the job row in the same DB transaction, a separate step/worker relays it to Redis) remains the right-sized fix; django-rq's `COMMIT_MODE='on_db_commit'` remains the closest packaged reference for the "commit-then-enqueue" semantic, with no raw-RQ + SQLModel equivalent existing as a library.

### #334 — PostgreSQL 18 evaluation
**Nothing new** beyond the version/CVE state already covered above.
