## Security Risks

### OPEN (7th cycle) — Starlette version floor below CVE-2026-48710 fix
`backend/requirements.txt` still pins `starlette>=0.49.1`, unbounded, no lockfile. Fixed version is 1.0.1 (minimum) / **1.3.1 is now the PyPI `latest`**, confirmed this cycle. Re-verified this repo's grep result is unchanged across three consecutive cycles: the only `request.url.path` usages are in the non-security correlation-ID middleware (`app/main.py`), and OAuth `redirect_uri` construction is sourced from `settings.frontend_url`, never request Host data (`app/api/auth.py:205,243`). **Confirmed not exposed to the secondary (post-patch) risk class.**
**Action:** change `starlette>=0.49.1` to `starlette>=1.0.1` (or `>=1.3.1` to track current) in `backend/requirements.txt`. One line, no behavior change.

Confirmed this cycle via the npm registry: `react`'s `latest` dist-tag is **19.2.7**, no newer patch has shipped. Any form submitted through a Server Action (auth, strategy save, profile settings) is a candidate for hitting this regression.
**Action:** bump `react`/`react-dom` to `19.2.7` in `frontend/package.json`.
