## Security Risks

### P0 — Next.js `16.2.6` behind security releases
Sources: [DEV: July 2026 release](https://dev.to/mr_manushukla/nextjs-july-2026-security-release-9-cves-patched-in-16211-and-15521-3o9b), [ecorpit: July release](https://ecorpit.com/nextjs-july-2026-security-release-cve-upgrade-2026/), [teramont: 16.3.3 critical RCE](https://teramont.net/blog/nextjs-16-3-3-15-5-24-critical-rce), [pkgpulse](https://www.pkgpulse.com/guides/nextjs-16-security-patches-cve-2026).
- July 2026: nine CVEs (four high, five medium) fixed in `16.2.11`.
- August 2026: a write-up reports two critical RCE issues fixed in `16.3.3`, most relevant to Windows servers or apps using the built-in AVIF image optimizer. Single secondary source; confirm against the official advisory.
- Vercel says security releases will now be published on a more regular schedule. Worth watching for an October batch; none surfaced.
- Whether the repo's Docker deployment (Linux) and image config are exposed is not assessed.
- A bump needs a stated justification and human approval per `AGENTS.md`. Verify with `cd frontend && npm test && npm run lint && npm run build`.

### P0 — Starlette floor too low
Sources: [GitLab: CVE-2026-48710](https://advisories.gitlab.com/pypi/starlette/CVE-2026-48710/), [InfoWorld](https://www.infoworld.com/article/4177714/fastapi-based-ai-tools-exposed-to-authentication-bypass-by-flaw-in-starlette-framework-2.html), [GitLab: CVE-2026-48818](https://advisories.gitlab.com/pypi/starlette/CVE-2026-48818/).
- CVE-2026-48710 ("BadHost"): unvalidated `Host` header used to rebuild `request.url`; affects versions before `1.0.1`. Severity ratings differ across sources (Moderate vs critical). InfoWorld frames it as an auth-bypass risk for middleware that keys off the URL.
- CVE-2026-54282 (fixed `1.3.0`) is from the 10-10 report and was not re-seen.
- CVE-2026-48818: `StaticFiles` UNC-path SSRF leaking NTLMv2 on Windows, fixed in `1.1.0`. `grep StaticFiles backend/app` returns nothing, and the deployment is Linux Docker, so likely not applicable.
- Repo finding: `request.url.path` used at `backend/app/main.py:71` and `:83`. Not checked: auth dependencies, CORS and rate limiting (Redis-based per `product.md` §2.1). `requirements.txt` pins `fastapi==0.136.1` with `starlette>=0.49.1`, so the installed version depends on resolution at build time. Check with `pip show starlette` in the container.
- Touches the auth surface, so human approval is required.

### P1 — React Server Components DoS (resolved by current pin)
Sources: [GitLab: CVE-2026-23870](https://advisories.gitlab.com/npm/react-server-dom-turbopack/CVE-2026-23870/), [GitLab: CVE-2026-23869](https://advisories.gitlab.com/npm/react-server-dom-parcel/CVE-2026-23869/).
- CVE-2026-23870 (High, 7.5): affects `19.2.0`–`19.2.5`, fixed in `19.2.6`. The repo pins `react 19.2.6`, so it is covered, assuming the bundled RSC runtime in Next.js matches. A Next.js bump should keep it that way. No official React advisory page was found for this one.

### P1 — PostgreSQL image currency
Sources: [AhnLab advisory (CVE-2026-6476)](https://asec.ahnlab.com/en/93764/), [Releasebot PostgreSQL feed](https://releasebot.io/updates/postgresql/postgresql).
- May 14 2026 release (18.4, 17.10, 16.14, 15.18, 14.23): 11 security fixes and 60+ bugs, including CVE-2026-6472 (`CREATE TYPE` authorization), CVE-2026-6476 (`pg_createsubscriber` SQL injection), CVE-2026-6478 (MD5 auth timing side channel).

- A pending 16.15 (from a tracker seen on 10-10) is still unconfirmed; check [postgresql.org/support/security](https://www.postgresql.org/support/security/).
