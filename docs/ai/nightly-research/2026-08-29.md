## Security Risks

### P0, NEW THIS CYCLE — Next.js: two critical unauthenticated RCEs (CVSS up to 9.0), fix is 16.3.3, repo still on vulnerable 16.2.6
Verified live via the official [Next.js August 2026 Security Release](https://nextjs.org/blog/august-2026-security-release) (published 2026-08-25) plus GitHub Advisories and the npm registry (`next@16.3.3` published 2026-08-25):
- **GHSA-2xp9-vwfh-vxw4** — RCE via AVIF image optimization (an upstream `libheif`/`sharp` flaw); Next.js's own mitigation was to disable AVIF optimization by default in the patched release.
- **CVE-2026-75604 / GHSA-p293-qw3h-jr36 (CVSS 9.0, CWE-22 path traversal)** — unauthenticated RCE, but scoped to **Windows-hosted** servers running Pages Router + App Router without Cache Components. **No workaround exists.**
- Both affect versions **16.0–16.3.2** — the repo's pinned **16.2.6 is in the vulnerable range for both.**
- The previously-tracked **CVE-2026-64649** (GHSA-89xv-2m56-2m9x, SSRF) and **CVE-2026-64648** (GHSA-68g3-v927-f742, cache confusion) are both still current/unpatched-in-repo — re-confirmed live, published 2026-07-21, unchanged this cycle. A third sibling advisory in that same batch was also confirmed this cycle: **GHSA-4633-3j49-mh5q** (cache confusion via invalid UTF-8 request bodies, Moderate, CVSS 6.3) — not new-to-window (same 2026-07-21 publish date), but newly individually verified.
**Action (escalated from P1 to P0):** bump `"next": "16.2.6"` to **16.3.3** (not 16.3.1 — that target is now stale). This single bump closes all of the above.
