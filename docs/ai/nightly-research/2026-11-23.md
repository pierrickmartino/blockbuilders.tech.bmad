**#510 (shared validator).** The UX search found one relevant pattern. Typed-port editors constrain connections at wire time (Flume's typed ports, yWorks' rule that outputs connect only to inputs with no duplicate edges, ingooutgo's snapping to compatible sockets). Our validation runs on a request and then highlights blocks (§3.3, §4.9). A shared validator that can also run client-side (the Health Bar, §4.17, already does this for completeness) would let the canvas reject invalid wires early. Whether our block ports are typed enough to support this was not checked. A Node-RED thread warns that node-level validation can override field-level validation on save. A shared validator should define which level wins.

## Implementation References

- **FastAPI body limits.** Official docs: fastapi.tiangolo.com/advanced/request-body-limits/. `max_body_size` (bytes) can be set on the app, an `APIRouter`, `include_router()` or a single path operation. Oversize bodies return HTTP 413. A separate `form_limits` setting returns 400 when parser limits are exceeded. This needs a FastAPI bump and a version check against the official release notes. Since 0.136.1 to 0.164.0 spans many releases, read all of them for breaking changes first. Yesterday's report said 0.163.0 drops Python 3.10 support (unverified, no effect on our 3.12).
- **SQLModel.** Read the full 0.0.38 to 0.0.50 notes at sqlmodel.tiangolo.com/release-notes. Check that Alembic autogenerate and our models behave the same on a branch. This is backend and touches migrations tooling, so it needs human approval under `AGENTS.md`.
- **Tailwind 3 to 4 and TypeScript 5.9 to 6.0.** Both are separate scoped migrations, not urgent. Tailwind 4 changes configuration style and will touch shadcn/ui setup. Run the official upgrade tool on a branch before estimating. TypeScript 6.0 is described as the bridge to the Go-based 7.0, so a 5.9 to 6.0 step is the lower-risk path and can come first. Neither migration was researched past release dates.
- **`@xyflow/react`.** 12.11.2 is the newest found, and our caret range already allows it. A search of release notes found 12.10.1 (Feb 19, connection-callback fixes and a zoom performance fix with pan-on-scroll), 12.10.2 (Mar 27) and 12.11.0 (Jun 1, contents unseen). Run `npm view @xyflow/react version` to confirm nothing newer.
- **Postgres and Next/React bumps.** See yesterday's report for the steps. Nothing new found.
- **Visual strategy builder UX.** Today's search returned library docs and forum threads, not trading-builder research.
  - Typed ports and connection-time rules are the common pattern (Flume, yWorks, ingooutgo). nodety is a Rust library for type inference and generics validation across a node graph. It is a reference for the idea, not something to adopt.
  - Protocol Labs' dataflow-editor write-up keeps editor state JSON-serializable with fixed named ports. This matches our block definition format (§4.3).
