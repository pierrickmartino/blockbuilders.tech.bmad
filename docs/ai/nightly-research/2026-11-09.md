## Executive Summary

1. **The Next.js target version is now confirmed.** The official November 2026 security release (published 2026-11-03) fixes seven issues (one high, six medium) in **16.4.5** and 15.5.29. The repo pins `16.2.6`. Upgrading needs human approval.
2. **The repo is probably not exposed to most of these seven issues.** A grep of `frontend/` found no `use cache`, `unstable_cache`, `cacheComponents`, Edge runtime or `x-middleware` usage. `next.config` sets `output: "standalone"` and has no `images` config. The cache and Edge-cookie advisories need those features. The `next start` shell-poisoning advisory also requires Cache Components. The grep covered only `.ts/.tsx/.js/.mjs` files, so treat this as indicative. The older 2026 releases (May to October) cover other issues, including a middleware bypass, RSC DoS and RCE bugs. This report has not checked the repo against those. The upgrade is still worth doing.
3. **The Image Optimization SVG bypass may apply.** It affects apps using the optimizer with `dangerouslyAllowSVG: false`, which is the default. Whether the app uses `next/image` with a remote source is unchecked.
4. **FastAPI and Starlette have advisories in the search results that need verification.** CVE-2026-48817 (non-standard HTTP method) and CVE-2026-54282 (request-path poisoning of `request.url.hostname`, published 2026-06-22) are both Starlette issues. The repo allows `starlette>=0.49.1`, so a fresh install will likely be patched, but the lock state was not checked.
5. **Open issues are unchanged.** The three `ready-for-agent` issues remain blocked on human PostHog setup.

## Implementation References

- **Next.js upgrade path:** the advisory gives `npm install next@16.4.5`. The page's comment says "for 16.5", which looks like a typo. Use the package version, not the comment. After the bump, run the frontend gate from AGENTS.md: `npm test && npm run lint && npm run build`. Also check `standalone` output and the Docker build, since the repo uses `output: "standalone"`. [nextjs.org](https://nextjs.org/blog/november-2026-security-release)
- **React Flow:** the "what's new" page lists 12.12.0 (`onResizeEnd` always fires after `onResizeStart`, resize value fix) and 12.11.x performance work. These are minor and the caret range admits them. Resize behaviour is not used by the current block nodes as far as product.md shows. [reactflow.dev](https://reactflow.dev/whats-new)
- **FastAPI:** the latest seen release is 0.142.2 (2026-09-30), per a translated release-notes page. [FastAPI release notes](https://fastapi.tiangolo.com/release-notes/). The 11-02 report mentioned breaking changes to parameter and form models in later 0.16x releases. That conflicts with this number, so the real latest version is still unknown.
- **Guided start on top of a node canvas:** the Raven builder generates a full strategy from a short guided flow, converts it to an editable node canvas, and lets users fine-tune manually. This matches the Blockbuilders wizard and its "build manually" escape hatch (§4.4). [DEV Community: Raven](https://dev.to/emilanielsen/building-a-no-code-trading-bot-builder-for-prediction-markets-raven-26fp)
- **Block categories:** the guides split strategies into entry, exit and filter blocks, and Composer uses one node per operation. Blockbuilders has input, indicator, logic, signal, exit and risk categories. [Composer review](https://dev.to/pickuma/composer-review-automated-trading-strategies-without-writing-code-lj3), [Backtrex guide](https://backtrex.com/en/blog/visual-trading-strategy-builder-no-code)
- **Non-graph alternative:** TradingView's Strategy Builder uses menus with AND/OR rules instead of a graph. This is a possible simpler mode for beginners, but it would be a product decision.
- **Backtest outputs:** vendors typically show expectancy, profit factor, Sharpe, max drawdown, win rate and average win-to-loss ratio. Blockbuilders shows five default metrics and hides the rest (§5.4). Expectancy and profit factor are not in the current metric list. This is an observation, not a recommendation.

All UX sources are vendor docs or blog posts, not usability research.
