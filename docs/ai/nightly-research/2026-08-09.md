## Implementation References

### #509 — Block Catalogue dispatch-table refactor
No ready-made cross-language "single source of truth" library exists. Two reference points worth citing in a future spec, neither directly adoptable:
- **WordPress `block.json`** — a mature, real-world precedent for "one JSON file is the canonical source, read by two different runtimes" (PHP `register_block_type()` + JS `@wordpress/blocks`). Clean architectural analogy for the FE canvas / BE validator / BE interpreter split this issue targets.
- **`glideapps/quicktype`** (actively maintained, pushed 2026-08-08) — generates typed models for 20+ languages from JSON Schema, but only structural types/serializers, not Pydantic validators or business-rule logic. Doesn't actually collapse the fork; still 2-3 hand-written validation implementations either way.
**Recommendation unchanged in substance:** treat as bespoke architecture — JSON Schema as the canonical block-definition format, feeding both a Python interpreter/validator and a generated frontend schema (see #510 below for the generation path).

### #510 — Pydantic → Zod codegen seam (materially new finding)
The three previously-identified direct converters remain confirmed dormant (re-checked via GitHub API `pushed_at`, no change):
- `dmitryrechkin/json-schema-to-zod` — `pushed_at` 2025-03-10
- `argyle-engineering/pydantic2zod` — `pushed_at` 2025-05-28
- `phillipdupuis/pydantic-to-typescript` — `pushed_at` 2024-11-22 (issue/comment activity continues through 2026-08-06, but zero code pushes)

**New this cycle:** routing through FastAPI's own auto-generated OpenAPI schema, then using an OpenAPI→TS/Zod generator, has actively-maintained options:
- `openapi-ts/openapi-typescript` — `pushed_at` 2026-08-09 (today), 8.3k★
- `astahmer/openapi-zod-client` — `pushed_at` 2026-08-05, 1.2k★
- `hey-api/hey-api` (openapi-ts) — `pushed_at` 2026-08-06, 5.2k★

**Recommendation:** don't adopt any of the three dormant point-to-point converters. Prototype the FastAPI-OpenAPI → `openapi-zod-client` (or `hey-api/openapi-ts`) pipeline instead — same end result (generated Zod/TS from the backend Pydantic models) but on dependencies with commits in the last 5 days rather than tools abandoned 14–21 months ago. This is a genuinely better starting point than what any prior cycle surfaced for this issue.

### #511 — Atomic `submit()` / commit-then-enqueue seam
`hyzyla/outbox-streaming` — still dormant, `pushed_at` 2023-02-05, confirmed unchanged. No Python/RQ-specific outbox library exists, then or now. Two actively-maintained but wrong-language repos surfaced as design references only (not adoptable): `Zehelein/pg-transactional-outbox` (TypeScript, `pushed_at` 2026-05-13) and `Kuper-Tech/sbmt-outbox` (Ruby, `pushed_at` 2026-02-26, uses Redis as coordinator). **Recommendation unchanged:** hand-roll — an `outbox` table written in the same transaction as the strategy-version insert, plus a small relay worker polling it and calling `queue.enqueue()`.

### #618/#620 — NL-wedge onboarding (materially new market evidence)
- **Composer.trade "Trade with AI"** (launched Oct 2025, still live under SoFi) — NL prompt → fully backtested visual strategy graph in <60s, then user edits it on their existing no-code canvas. Closest direct analog to the #618 hypothesis, already shipped by a funded competitor. No public conversion metrics.
- **n8n AI Workflow Builder** (Cloud rollout Oct 2025) — NL prompt generates a complete node graph directly on canvas; explicitly framed by n8n as the fix for the "blank canvas problem." No public completion-rate numbers.
- **Zapier Canvas** (late 2025) — deliberately does *not* let NL generate the final executable graph; NL produces a recommended visual *plan*, user builds the actual automation from that plan. A "NL for scaffolding, not final output" middle ground worth considering as a third option beyond the pure wizard-vs-NL binary #618 currently frames.
- **Coinrule MCP** (available Feb 2026) — a different wedge entirely: NL strategy creation happens outside the canvas via external AI agents (ChatGPT/Claude/Grok) talking to Coinrule through MCP, which then materializes rules in the existing builder. Suggests an alternative to building in-app NL parsing: expose an MCP/agent interface instead.
