## Security Risks

### P0 — Next.js `16.2.6` behind security releases
Sources: [lilting.ch, 16.2.6/15.5.18 summary](https://lilting.ch/en/articles/nextjs-security-release-16-2-6-15-5-18), [DEV: July 2026 release](https://dev.to/mr_manushukla/nextjs-july-2026-security-release-9-cves-patched-in-16211-and-15521-3o9b), [Teramont: July 2026](https://teramont.net/blog/nextjs-9-vulnerabilities-july-2026-16-2-11-15-5-21), [pkgpulse](https://www.pkgpulse.com/guides/nextjs-16-security-patches-cve-2026).
- July release: 9 CVEs fixed in `16.2.11`, four rated high, including a Middleware/Proxy bypass (CVE-2026-64642) for App Router apps built with Turbopack and a single locale.
- A Teramont page headline reports two critical RCEs (Windows servers, AVIF image optimization) fixed in `16.3.3`/`15.5.24`. It is undated and uncorroborated.
- Whether the app uses Turbopack, a single locale, middleware, or AVIF optimization was not checked.
- A bump needs a stated justification and human approval per `AGENTS.md`. Verify with `cd frontend && npm test && npm run lint && npm run build`.

### P0/P1 — React `19.2.6` possibly in a DoS-affected range (new)
Sources: [TuxCare CVE-2026-44907](https://tuxcare.com/cve-tracker/cve/details/cve-2026-44907/), [react.dev RSC advisories](https://mn.react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components).
- TuxCare lists `19.2.0`–`19.2.7` as affected, fixed in `19.2.8`. Publication date and official react.dev confirmation not found.
- Earlier RSC advisories (CVE-2025-55182 RCE, CVE-2026-23864, CVE-2026-23869) were fixed by `19.2.1`, `19.2.4`, `19.2.5`; the pin is past those.
- Affected only if Server Components are in use. Treat as P1 until confirmed, P0 if confirmed. `react` and `react-dom` must move together.

### P0 — Starlette floor too low (*carried*)
`starlette>=0.49.1` allows versions affected by CVE-2026-48710 (fixed 1.0.1) and CVE-2026-54282 (fixed 1.3.0), both about unvalidated request data used to rebuild `request.url`. Exposure depends on whether auth, CORS or rate-limit code keys off `request.url`; not checked. Touches the auth surface, so human approval is required. Not re-searched this cycle.

### P1 — PostgreSQL image currency
Sources: [postgresql.org security page](https://www.postgresql.org/support/security/18/), [AhnLab advisory (CVE-2026-6476)](https://asec.ahnlab.com/en/93764/), [Releasebot summary](https://releasebot.io/updates/postgresql/postgresql).
- May 14 2026 release (`18.4`, `17.10`, `16.14`, `15.18`, `14.23`) fixed 11 security issues, including CVE-2026-6473 (integer wraparound, CVSS 8.8), CVE-2026-6477 (libpq large-object stack overflow) and CVE-2026-6478 (MD5 auth timing side channel). Version-to-CVE mapping is from secondary sources; verify before relying on it.
- The 10-10 report mentioned an unconfirmed `16.15` batch. Not re-found this cycle.
- `postgres:16` floats on the minor. Confirm `SELECT version();` shows `16.14` or later after pulling and recreating. The deployed tag was not checked.
- PostgreSQL 14 reaches end of life 2026-11-12; not applicable to the repo's 16.

## Implementation References

- **Upgrade order (suggested):** React/React-DOM `19.2.8` → Next.js `16.2.11`+ (stay on the 16.2 LTS line unless a human approves 16.3) → Starlette floor. Each is a dependency change that needs a justification note.
- **TypeScript 7:** [InfoQ](https://infoq.com/news/2026/08/typescript-7-released/) and [Visual Studio Magazine](https://visualstudiomagazine.com/articles/2026/06/22/typescript-7-0-rc-moves-microsofts-go-rewrite-into-the-mainline-compiler.aspx) report that code clean on 6.0 (without `ignoreDeprecations`) compiles identically on 7.0. A staged path would be 5.9 → 6.0 → 7.0, with CI type-check as the gate. No programmatic API yet for embedded tooling.
- **FastAPI:** newer releases add `app.frontend()` for serving a built frontend (0.138+). Not relevant to this stack's separate Next.js frontend; no action. [Release notes](https://fastapi.tiangolo.com/release-notes/).
- **XyFlow v12 notes:** node dimensions live in `node.measured.width/height`; `useNodesData`, `updateNodeData` and `colorMode` exist. Relevant if auto-layout (product §4.16) uses dagre/elk. [Migration guide](https://reactflow.dev/learn/troubleshooting/migrate-to-v12), [what's new](https://reactflow.dev/whats-new).
- **Tailwind 4:** CSS-first config, much faster builds; the migration touches every component's styling and shadcn/ui config. Not recommended as an overnight slice. [Release overview](https://laravelnews.substack.com/p/tailwind-css-v4-is-here).
- **Visual builder UX patterns** (competitor descriptions, mostly marketing claims):
  - Three block families (indicators, comparison logic, entry/exit actions) matches the product's existing model; [Backtrex docs](https://backtrex.com/en/docs/getting-started/introduction).

  - Caveat from [a DEV article](https://dev.to/reyazk08/no-code-strategy-builder-turning-a-trading-idea-into-testable-rules-31ji): visual builders struggle with multi-timeframe and portfolio-level logic, consistent with the single-asset, single-timeframe MVP constraint.
