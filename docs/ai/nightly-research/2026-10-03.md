## Executive Summary

1. **Redis:** the repo pins `redis:7.4.9-alpine`. Redis disclosed CVE-2026-81934, a TLS use-after-free that could allow RCE for an authenticated attacker. The fix is in 7.4.11. Redis rates it High (CVSS 7.5), though the initial CVE record said 9.8. Bumping the image tag is a one-line infra change. Redis holds the RQ queue, OAuth state and the password-reset rate limits.
2. **Starlette:** CVE-2026-48710 ("BadHost") is a Host-header handling flaw that can bypass path-based security checks. CISA added it to the KEV catalog on 2026-09-02. Versions before 1.0.1 are affected. `backend/requirements.txt` has `starlette>=0.49.1` with no upper bound. Whether the deployed image is safe depends on what pip resolved at build time. There is no lockfile evidence either way, so this needs checking.
3. **Next.js:** still pinned at `16.2.6`. Version `16.3.8` (2026-09-30) fixes seven issues, including a high-severity SSRF in Image Optimization. It also covers the `16.3.6` upstream-critical fix. The 10-02 report records further critical and high issues as deferred upstream, so expect another release.
4. **PostgreSQL:** the 2026-09 minor releases (16.15 and others) fix CVE-2026-6471, a missing-authorization flaw in logical decoding (CVSS 7.2). The repo uses `postgres:16-alpine`, a floating tag. Confirm that deployed hosts have pulled 16.15.
5. **No active-issue state change.** Open issues are the same as in the 10-02 report. The `ai-ready` label is unused; the tracker uses `ready-for-agent`.

## Security Risks

Ranked by exposure. None of these has been exercised against the repo; they are advisory-based.

### P0 — Starlette Host-header bypass (CVE-2026-48710, CISA KEV)
- **Affected:** Starlette before 1.0.1 (CVSS 6.5 Moderate, but actively exploited per KEV).
- **Repo exposure:** `starlette>=0.49.1` with no cap. A fresh build probably resolves a fixed version, but an old cached layer or lock may not.
- **Check:** run `pip show starlette` inside the current backend image. If it is below 1.0.1, rebuild.
- **Open question:** Starlette 1.x is a major version. Confirm FastAPI 0.136.1 supports it before relying on the floating range.
- Whether any Blockbuilders route relies on host- or path-based middleware to protect it is unknown. This needs a human or backend review.

### P0 — Redis 7.4.9 (CVE-2026-81934)
- Use-after-free in TLS pending-data processing. It needs authentication and TLS. The repo's compose Redis is probably internal-only, which would lower exposure; this was not verified.
- Fixed in 7.4.11. Bump `docker-compose.yml:98` and `docker-compose.prod.yml:97`.
- CVE-2026-66373 (RESTORE double free) affects Redis before 8.8.0. The advisory pages did not state whether 7.4.x is affected. Treat that as unknown.

### P1 — Next.js 16.2.6
- The 2026-09-30 release `16.3.8` fixes a high-severity SSRF in Image Optimization, plus cache poisoning for self-hosted SSG/ISR, App Router metadata image-route disclosure, and a Draft Mode leak in `use cache`.
- The 10-02 report notes that `16.3.6` fixed an upstream `next/og` RCE and that the repo imports `next/og` on a public share route. I did not re-verify that this cycle.
- CVE-2026-75604 (backslash escaping in incremental-cache paths) only matters on Windows-hosted servers. The Docker deployment is not affected.
- A Next.js bump changes the frontend runtime. It is not in `AGENTS.md`'s high-risk list, but it should go through the normal test run (`npm test && npm run lint && npm run build`).

### P1 — PostgreSQL 16 minor currency
- Fixes: 16.15 for CVE-2026-6471 (logical decoding authorization), and the May 2026 batch of 11 CVEs (16.14).
- The repo floats `postgres:16-alpine`. A pull gets the newest 16.x, but running hosts only update when the image is re-pulled and the container recreated.
- Logical decoding is exposed only to roles with replication access. The repo likely does not use replication. Verify before downgrading the priority.

### Not found
- No advisories turned up for SQLModel, Alembic, `@xyflow/react`, or RQ in this search. That is absence of evidence, not a clean bill.
