## Executive Summary

1. **The React Server Components RCE flagged as "unverified" on 2026-11-18 is real.** `facebook/react` lists GHSA-xqc2-xf4c-x3h3 (CVE-2026-126187), Critical, CVSS 9.5, published **2026-10-14**. Affected: `react-server-dom-webpack/parcel/turbopack` 19.0.0–19.0.8, 19.1.0–19.1.9, 19.2.0–19.2.8 and 19.3.0. Patched: 19.0.9, 19.1.10, 19.2.9, 19.3.1. Our `react` pin is `19.2.6`, which is inside the affected range. The "2026-11-10" date in third-party posts was wrong. Whether we are exposed depends on how Next vendors its RSC runtime (see Security Risks).
2. **A second Critical applies to our Next.js pin.** GHSA-2464-fhr4-w9xw (CVE-2026-96889), CVSS 9.5, published 2026-10-14. It is an unauthenticated RCE in Image Optimization via an upstream library (`sharp`). Affected: `next` 10.0.0–15.5.27 and 16.x up to 16.4.0. Patched: 15.5.28 and **16.4.1**. Our `16.2.6` is in range. Per the advisory, only glibc-based Linux is affected. Our frontend image is `node:20-alpine` (musl) and the code has no `next/image` usage, so production exposure looks low. Dev machines and CI on glibc are not excluded.
3. **Recommended bump: `next` to at least 16.4.1, ideally the current 16.4.x patch.** This addresses both Criticals and the seven Moderate advisories published 2026-11-03. Upgrading is a human decision. Dependency changes need explanation under `AGENTS.md`. Use the Questions section.
4. **PostgreSQL 2026-11-12 batch (52 CVEs).** Fixed in 18.7, 17.12, 16.16, 15.20 and 14.25. The highest is CVE-2026-6460 (CVSS 8.8, authenticated type confusion). PG 14 is now EOL. Our floating `postgres:16-alpine` tag only reaches 16.16 after a pull and container recreate. Confirm prod is on 16.16.
5. **FastAPI is about 27 minors behind (`0.136.1` vs `0.163.x`).** A "Breaking Changes" entry was reported in 0.162.6 (see the 2026-11-18 report). Its contents are unread. New releases also require AnyIO ≥ 4.1.0 (search summary, unverified). Read the notes before any bump.
6. **Open issues unchanged since 2026-11-18.** `ready-for-agent` issues #618, #570 and #555 are each blocked on a `ready-for-human` PostHog task. Nothing is actionable by an agent.

## Implementation References

- **Next/React upgrade path.** Read the official Next.js 16.3 and 16.4 posts (nextjs.org/blog/next-16-3, next-16-4) and the upgrade guide before bumping. Search snippets say 16.4 includes React 19.3 features and 16.3 was "the biggest update since 16.0". Check whether `react`/`react-dom` pins must move together (19.2.9 or 19.3.1 for patched RSC lines). Run `cd frontend && npm test && npm run lint && npm run build`.
- **Tailwind and TypeScript.** Our pin `tailwindcss 3.4.19` is the v3 line. Searches found no 2026 release information for Tailwind or TypeScript, so there is nothing to act on. A v4 migration would be a separate scoped task.
- **`@xyflow/react`.** 12.11.2 (2026-07-06) is described as performance-focused. Our range `^12.10.0` already permits it. 12.10.1 included fixes for `onConnectEnd` / `isValidConnection` staleness during an ongoing connection and for pan-on-scroll zoom performance. Relevant to our touch/tap-to-connect work (§4.11). Full changelogs: github.com/xyflow/xyflow/releases.
- **FastAPI.** Per search: 0.162.3 adds Python 3.15 support and updates Pydantic. 0.162.4 requires AnyIO ≥ 4.1.0. The project now ships a coding-agent skill (`uvx library-skills`), which could be useful for our agent workflows. All unverified beyond the release-notes snapshot. SQLModel pins often constrain the FastAPI/Pydantic range, so test them together.
- **Visual strategy builder UX** (search; mostly product docs and dev blogs, not formal UX research):
  - Pattern: a guided or generated starting point, then a node canvas for fine-tuning, a live backtest loop, and (in some tools) an escape hatch to code. This matches our wizard (§4.4), canvas (§4) and templates (§3.7).
  - Raven generates a whole strategy and converts it to a node canvas. Its author flags that multi-node graphs overwhelm beginners. This supports the NL-wedge test in #618.
  - Composer uses one block per operation. MQL5 expression popups read like sentences, similar in spirit to our Strategy Explanation Generator (§4.8).
  - ClashX builds its node editor on xyflow, connecting condition nodes to action nodes.
  - Real-time backtesting is the most praised feature in reviews, and we already offer it.
- **#570 / #555 / #618.** All hinge on PostHog experiments and cohorts. No new library research was needed beyond what ADR-0010 records.
