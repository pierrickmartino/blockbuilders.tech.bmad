## Executive Summary

1. **Next.js `16.2.6` is behind the official 2026-11-03 security release.** I read the advisory itself: one High and six Medium issues, all fixed in 16.4.5. Most of them need Cache Components or `use cache`, Edge route handlers, a self-hosted `next start` behind a particular proxy, or the image optimizer. Whether we are exposed depends on which of those the app uses. That has not been checked in the code tonight. Upgrading needs human approval.
2. **SQLModel is now 11 patch versions behind (0.0.38 vs 0.0.49), and 0.0.45 is a breaking datetime change.** `datetime` fields default to timezone-aware UTC, and naive values sent to the database raise an error. Existing databases are not changed automatically. We store `created_at`/`updated_at` and compute backtest date ranges, so a bump needs a migration plan.
3. **Open issues are unchanged from last night.** The three `ready-for-agent` issues (#618, #570, #555) are still blocked on human PostHog setup (#620, #573, #561).
4. **No new FastAPI, Alembic, Redis or redis-py advisories surfaced.** The search returned nothing for them, which is not evidence of safety.
5. **UX research found nothing that argues for a change.** Visual builders in the market use one block per operation, AND/OR combination, and a separate results view, as we do.

## Implementation References

- **SQLModel UTC datetimes:** The release notes (*verified*) say datetime columns default to `DateTime(timezone=True)`, writes require timezone-aware values, and `NaiveDatetime` opts back into naive storage. "Existing databases are not changed automatically." On PostgreSQL the upgrade needs a column migration that states the timezone of existing values. The docs point to the "Upgrade Existing Applications" section of the Datetimes and Timezones guide. 0.0.46 fixed timedelta arithmetic with UTC datetime fields. 0.0.41 deprecated `min_items`/`max_items` on `Field`. I read the first 100,000 of 143,281 characters of that page. See [SQLModel release notes](https://sqlmodel.tiangolo.com/release-notes/).
- **Next.js upgrade path:** `npm install next@16.4.5`. The post labels 16.4.5 as Active LTS. It also lists 15.5.29 for the 15.x line.
- **React Flow:** The what's-new page I could see lists 12.11.2 dated 2026-07-06, focused on performance. Last night's report cited 12.12.0 around October. Tonight's searches could not confirm either as newest, and the jsDelivr and Snyk pages were stale. All are inside our `^12.10.0` range. Check the npm page before relying on a number. See [reactflow.dev what's new](https://reactflow.dev/whats-new/2026-07-06).

See [Backtrex guide](https://backtrex.com/en/blog/visual-trading-strategy-builder-no-code) and [Composer review](https://dev.to/pickuma/composer-review-automated-trading-strategies-without-writing-code-lj3).
